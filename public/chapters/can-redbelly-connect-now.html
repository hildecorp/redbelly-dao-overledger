05The answer

Can Redbelly connect now, and what is missing?

A connection can mean three different things. Each has a different answer.

Analysis

Level 1: reaching Redbelly through the Overledger Gateway. Possibly, unconfirmed.

Redbelly is EVM compatibleS2, and Overledger's self-serve EVM family is described as covering EVM-compatible chainsS3. An unlisted network in a self-serve family can be added by the first node registrationS3. At the RPC level Redbelly appears to fit the self-serve testsS3: its RPC works over HTTPS and answered without a key, two different endpoints returned the same chainS4, and its write rule is attached to accountsS5, not to the node a client uses. Ankr, an approved providerS3, runs a Redbelly mainnet endpointS16, and the official RPC could be added as a private nodeS3.

Analysis

If it works, this level would give an institution one interface to read Redbelly data and send transactions it has signed itself. After its own access checks, the Gateway forwards the payload to a Redbelly node and passes back the native response unchangedS3, so Redbelly's own rules still apply. A transaction sent this way only succeeds if the sending account has Redbelly write accessS5.

Unknown

Four points are open

  • How Overledger would classify Redbelly. Self-serve is written for public, permissionless networksS3, Overledger's own glossary calls a network where anyone can read but only allowlisted parties can write "public permissioned"S13, and permissioned EVM networks are on the engagement routeS3. The same docs send networks that need any other identity-bound configuration, and operator-gated public chains, to the engagement routeS3, and Redbelly selects its node operators by applicationS20. Writing to Redbelly needs an access credentialS5, so Redbelly could be treated as an engagement network; the docs do not say.
  • Which call the health check uses. The docs say only that it uses the chain's standard validationS3 and that a checker does a chain identifier lookupS3. If it relies on net_version, Redbelly's answerS4 could fail it.
  • Whether a provider's keyed service covers Redbelly. A public node URL must carry a provider API keyS3, and we did not confirm that Ankr's keyed service covers Redbelly.
  • Whether Redbelly is already listed. Overledger's live network listS3 and the Fusion Rollup's listS38 both answered "Missing authorization header" without an API keyS7, so we could not see it.
Analysis

Level 2: Overledger Flow Apps on Redbelly. Unknown.

Flow Apps are multi-step workflows run through the GatewayS12, and customers and partners can also host their ownS13. The catalogue is not listed in the public docs; only account holders can see which apps are available to themS14, and every shipped app is built by QuantS14, so whether a given app accepts a self-serve EVM network such as Redbelly cannot be checked from public sources. The docs give an effort of about a day per app only for adding a brand-new chain familyS3; they give no figure for a new network inside a family Overledger already supports.

Confirmed

Level 3: joining the Fusion Rollup.

The networks documented as connected at testnet launch are Ethereum Sepolia, Polygon Amoy and Quant's permissioned Besu testnetS6. Each connected chain carries the rollup's bridge and dispute contractsS6 and receives the rollup's state rootsS6. Token entries on the bridge are controlled by Quant's governance signersS37.

Analysis

Not possible yet, as far as public sources show.

Redbelly is not in the documented list, the live list could not be read without an API keyS7, and the documentation we read describes no self-serve way to add a chain to the Fusion Rollup. The Redbelly side looks light. Fusion is documented as supporting public and permissioned networks side by sideS6, and it posts transaction data to a single permissioned chain and only state roots to the othersS6, so a Redbelly deployment would carry the bridge and dispute contracts and state roots, not transaction data. Redbelly's access credential is not a blocker in principle: the accounts that deploy those contracts and post state roots would each need Redbelly network accessS5, which is a setup step. The documented gap is on the Quant side, because Redbelly is not in the connected list and no source shows Quant has connected it. No such work has been announcedS1.
